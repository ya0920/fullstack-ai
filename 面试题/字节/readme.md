# 字节
1. 什么是跨域？（请你聊一聊跨域问题）
 - 同源策略
    1. 浏览器出于安全考虑（出于数据安全，服务器安全，减少 XSS 和 CSRF 攻击），
    2. http:// www.   abc.com :8000 / a.html
       协议    子域名 主域名   端口号    路径
    3. 非同源，请求发送后，浏览器会拦截响应

 - 跨域方案
    1. jsonp
       1. script 标签 src 属性不受同源策略的限制（例如用iconfont库），来发送请求
       2. 携带一个参数 callback，给到后端
       3. 后端将数据作为 callback 的实参，返回给前端一个 callback 的调用形式
       4. 浏览器接收到 callback 的调用会自动执行全局的 callback 函数
    - 必须要前后端配合
    - 只能发送 get 请求
    - 不安全，容易受到脚本攻击

    1. CORS
       1. 后端设置 Access-Control-Allow-Origin：'域名白名单'，来通知浏览器里那些域名可以跨域访问

    2. nginx 反向代理
       1. 前端服务器和后端服务器不在同一个域名下，前端服务器通过 nginx 反向代理来访问后端服务器

    3. node 中间代理
       1. 前端服务器和后端服务器不在同一个域名下，前端服务器通过 nginx 反向代理来访问后端服务器

    4. websocket
       1. 传统的前后端通讯是基于 http 协议的，是单向的，只能从一段发送到另一端，无法双向通信
       2. websocket 是基于 tcp 协议的，是双向的，可以从一端发送到另一端，也可以从从另一端发送到一端
       3. scoket 协议一旦建立连接，就可以一直保持通信状态，不需要每次都建立连接
       4. 天生就可以跨域

    5. postMessage
       1. 当父级页面和 iframe 页面不在同一个域名下，他们之间的数据传输也存在跨域问题，父级页面和 iframe 页面之间可以通过 postMessage 来通信

    6. document.domain

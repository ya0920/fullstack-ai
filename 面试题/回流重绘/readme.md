# 浏览器渲染的过程
1. 解析数据包得到 html， css文件 （将二进制的字节数据解析成字符串）
2. 字节数据 => 字符串 => Token => Node 节点 => 构建 DOM 树
3. css 文件转成 CSSOM 树
4. DOM + CSSOM = render 树  （DOM 看不见的元素不会出现在renden书里）
5. 计算布局（回流） ---很耗费性能的

# 回流
1. 页面初次渲染
2. 窗口大小改变
3. 增加，删除可见的 DOM 元素
4. 改变可见的几何信息

# 重绘
1. 改变元素的非几何信息


- 字体的大小不算几何信息
- 回流一定重绘，重绘不一定回流

# 浏览器的优化（老版本没有）五六年前
浏览器内置了渲染队列，当浏览器执行到一个需要回流的操作之后，会先将该操作放入队列，浏览器继续往下执行，如果下面还有导致回流的行为，就一直入队列。直到队列达到阈值或者后面没有回流行为，才会将渲染队列中的行为一次性执行，并一次性修改样式。

# 强制执行渲染队列的属性、
1. offsetxxx(包含边框)top left right
2. clientxxx（不包含边框）
3. scrollxxx(监听页面的滚动)

# 减少回流
1. 先让元素脱离文档，再修改几何属性，再放回文档流 .style.display = "none" => "block
2. 使用虚拟文档
3. 使用克隆dom
